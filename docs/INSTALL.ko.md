# Windows 설치와 검증 안내

현재 패키지는 공개 합성 시험을 위한 소스 후보입니다. 실행기 변경의 빌드와 AppContainer 통합 검증이 완료되지 않았으므로 업무 설치 또는 공개 출시 승인본으로 사용하지 않습니다. 아래 절차는 검토된 소스에서 설치 후보를 재현하기 위한 절차이며 보안 승인 절차를 대신하지 않습니다.

## 준비 조건

Windows x64, 조직이 승인한 Python 3.12, .NET Framework C# 컴파일러가 필요합니다. 모델 실행은 CPU 경로만 구현합니다. GPU·CUDA 지원을 가정하지 않습니다. 고정 버전과 SHA-256은 의존성 잠금 파일과 모델 명세를 확인합니다.

설치 위치는 로컬 고정 디스크를 사용합니다. 네트워크 공유, 매핑된 네트워크 드라이브, 장치 경로, 대체 데이터 스트림, 경로 이탈, 재분석 지점 및 하드 링크를 준비 도구의 허용 경로로 사용하지 않습니다. 설치 담당자는 코드·런타임·모델과 무결성 기록을 일반 사용자가 변경할 수 없도록 조직의 승인된 권한 정책으로 보호해야 합니다. 패키지가 관리자 권한을 요청하거나 시스템 정책을 완화하지는 않습니다.

회사 자료가 없는 별도 준비 환경에서만 다운로드를 수행합니다. 다운로드 주소는 고정 명세의 HTTPS 공개 파일로 제한하고 리다이렉트도 허용 공급처인지 검사합니다. 환경 변수의 프록시나 인증 정보를 다운로드에 사용하지 않습니다. 조직의 프록시·허용 목록과 맞지 않으면 중단하고 반입 절차를 검토합니다. 주소 제한을 풀거나 인증 정보를 코드에 넣지 않습니다.

## 1. 공개 파일 준비

명령의 작업 폴더는 저장소 루트입니다. 이 단계에서는 모델을 실행하지 않습니다.

```cmd
python -I -S -B scripts\prepare.py download
```

`download`만 공개 파일 다운로드를 수행합니다. 기존 파일은 해시를 확인하고 재사용합니다. 해시가 다르거나 일부 다운로드만 남은 경우 파일을 보존하고 실패합니다. 임의 덮어쓰기·삭제·자동 재시도를 하지 않습니다. 원본 모델과 기존 검증 증거는 그대로 보존합니다.

## 2. 네트워크를 사용하지 않는 설치

검토된 소스와 해시가 일치하는 공개 아티팩트를 승인된 환경으로 반입한 뒤 수행합니다.

```cmd
python -I -S -B scripts\prepare.py install
python -I -S -B scripts\prepare.py verify
cmd.exe /d /c scripts\build.cmd
python -I -S -B scripts\prepare.py seal
build\LayaLauncher.exe --setup
```

각 명령은 종료 코드와 출력 검증을 확인한 뒤 다음 단계로 진행합니다. 컴파일이나 격리 설정이 실패하면 이후 실행을 중단합니다. 이전 실행 파일로 새 소스의 무결성 기록을 만들거나 다른 실행 경로로 격리 검사를 생략하지 않습니다.

`install`은 이미 받은 아티팩트만 사용하며 전역 Python 환경을 변경하지 않습니다. `runtime-v2` 또는 준비된 모델 폴더가 이미 있으면 보존하고 중단합니다. 기존 설치는 재설치 대신 `verify`로 확인합니다. 토크나이저 호환 변환은 준비 사본에만 적용하며 원본 모델은 수정하지 않습니다.

`verify`는 다운로드 파일, 설치된 Python, wheel의 설치 파일, 준비된 모델, 공개 합성 자료의 해시를 확인합니다. 런타임·준비 모델에 예상하지 못한 파일이 있으면 실패합니다. 이 검사는 취약점 진단이나 악성 코드 부재의 증명이 아닙니다.

내장 Python의 경로 파일 `runtime-v2/python312._pth`에는 `python312.zip`, `.`, `Lib/site-packages` 세 줄만 둡니다. `import site` 줄을 넣지 않습니다. 이 줄이 있으면 `-S`를 지정해도 시작 시 `site`가 로드되며, 기존 런타임에서 이 동작이 관찰됐습니다. worker는 `site`가 로드된 시작을 거부합니다. 이전 경로 파일로 설치된 기존 런타임은 새 `verify`에서 `UNEXPECTED_PYTHON_SEARCH_PATH`로 실패하며, 수정된 것으로 간주하지 않습니다. 기존 런타임은 보존하고, 적절히 검증된 새 설치 후보가 준비될 때까지 사용하지 않습니다. 실행기 빌드와 이에 의존하는 런타임 재설치·봉인은 현재 중단 상태입니다.

`seal`은 검증이 성공한 설치의 상대 경로와 해시를 `build/offline-integrity.tsv`에 기록합니다. 실행기는 Python을 시작하기 전에 이 기록과 실행 파일·모델·소스 바이트를 확인합니다. 기존 기록이 달라지면 이전 기록을 보존합니다. 이 기록은 로컬 변경 탐지 수단일 뿐 전자서명, 조직 승인 또는 업무 입력 활성화 토큰이 아닙니다.

`--setup`은 이 설치 위치 전용 AppContainer 프로필과 파일 접근 권한을 준비합니다. 런타임·코드·준비 모델은 읽기/실행, `private` 폴더는 합성 결과 기록 용도로 설정합니다. 네트워크 capability는 부여하지 않습니다. 다른 프로그램의 방화벽, 네트워크 어댑터, 실행 정책 또는 보안 제품 설정은 변경하지 않습니다.

## 3. 합성 검증

단위·부정 시험의 개발 증거는 저장소 밖에 보관합니다.

```cmd
python -I -S -B tests\test_security.py --evidence-dir ..\validation
python -I -S -B tests\test_guards.py --evidence-dir ..\validation
build\LayaLauncher.exe evaluate private\synthetic-run-001.json
build\LayaLauncher.exe probe private\probe-run-001.json
```

경로 인수는 아직 존재하지 않는 결과 이름입니다. `evaluate`는 해당 입력 파일을 읽지 않고 해시가 고정된 `tests/synthetic-ko.json`만 처리합니다. 회사 자료를 이 경로에 저장하지 않습니다. 이미 존재하는 입력 또는 결과 이름은 거부하므로 다음 시험은 새로운 이름을 사용합니다. 결과 파일은 `private`에 기록하며 공개 소스에는 포함하지 않습니다.

실행기는 Python을 정지 상태로 생성한 뒤 단일 프로세스 제한과 종료 시 자식 종료가 설정된 job에 배치하고 실행합니다. worker는 AppContainer 토큰, capability 수, 예상 컨테이너 식별자 및 job 제한을 확인합니다. 실패하면 모델 처리 없이 종료합니다. 합성 실행은 180초 제한을 사용합니다. 이 구현의 실제 통합 검증은 현재 미완료입니다.

`probe`는 종전의 명시적 API 접근 거부 조건을 유지합니다. UDP 송신 함수의 성공이나 연결 거절·시간 초과를 차단 성공으로 바꾸지 않습니다. 이 검사 전체가 성공하더라도 전체 외부 송신 경계가 인증된 것은 아닙니다.

`native-probe`와 `guard-check`는 통합 검증 담당자용 합성 모드입니다. 전자는 네이티브 TCP/UDP/IPv4/IPv6/루프백 및 DNS 결과를 수집하는 소스 도구이며 수신측 양성 대조군과 패킷 증거를 별도로 준비해야 합니다. 후자는 고정된 공개 canary 준비 및 호스트 접근 양성 확인이 필요합니다. 필수 조건이 없으면 NOT_RUN으로 기록합니다. 현재 후보의 해당 통합 시험은 완료되지 않았습니다.

## 회사 환경의 적용 범위

회사가 승인한 Claude·GPT Enterprise 사용은 그대로 유지합니다. Laya의 별도 외부 전송을 막는 실행 경로를 검증하며 PC 전체 인터넷 차단, 관리자 권한 또는 VM 설치를 기본 필수 조건으로 두지 않습니다. Laya 실행 중 다운로드, 텔레메트리, 원격 오류 보고 및 외부 API fallback을 허용하지 않습니다.

현재 후보는 새 실행기의 빌드·통합 검증이 남아 있어 공개 합성 시험용으로만 다룹니다. 업무 입력 CLI/API도 아직 제공하지 않습니다. 회사 자료 사용 전에는 변경된 실행기의 통신 차단·실패 경로·로컬 추론을 검증하고 업무 입력 인터페이스에 대한 별도 검토를 완료해야 합니다.

회사 보안 정책이 추가 격리를 요구하면 그 정책을 따릅니다. 다른 프로그램의 방화벽이나 Enterprise 연결을 임의로 변경하지 않습니다. 결과 폴더는 회사가 승인한 위치를 사용하며 공개 GitHub나 개인 동기화 폴더에 회사 자료를 저장하지 않습니다.

## 업데이트와 보존

자동 업데이트, 자동 제거 또는 영구 삭제 도구를 제공하지 않습니다. 원본 모델, 이전 무결성 기록 및 검증 증거를 보존합니다. 필요한 파일 정리는 조직 정책과 실제 복구 가능한 운영체제 휴지통을 사용합니다. 휴지통 이용을 보장할 수 없으면 파일을 유지합니다. 실행 정책 변경, Bypass, 일괄 차단 해제 또는 차단된 스크립트의 우회 실행을 사용하지 않습니다.
