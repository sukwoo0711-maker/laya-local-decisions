## 구현된 방어와 한계

Claude의 독립 소스 검토에서 Python 시작 설정 충돌을 발견했습니다. 기존 런타임은 `-I -S -B`로 시작해도 `no_site=0`, `site_loaded=true`를 반환했습니다. 준비 도구의 `PTH` 상수에서 `import site`를 제거했고, 수정 후 Python 경계 시험 14개가 통과했습니다. 기존 런타임 파일은 보존했으며 새 기준으로 갱신하지 않았습니다. 따라서 현재 설치본은 새 `verify`의 정확한 경로 파일 비교를 통과할 수 없고, 변경된 실행기의 빌드·통합 검증과 새 설치 후보 확인이 남아 있습니다.

업무 입력 모드는 파일 처리 전에 거부하도록 구현합니다. 합성 평가는 고정 SHA-256과 일치하는 공개 자료만 사용합니다. 별도 설정 파일, 환경 변수 또는 검사 결과를 수정하여 업무 입력을 활성화하는 경로를 제공하지 않습니다.

다운로드는 준비 단계에만 존재합니다. 설치·검증·무결성 기록 생성은 이미 받은 로컬 아티팩트만 사용합니다. 다운로드의 공급처, HTTPS, 인증 정보 없는 주소와 리다이렉트를 검사합니다. 모델 실행 경로에는 외부 추론 API fallback을 제공하지 않습니다.

고정된 Laya 0.3.22 소스의 로딩 경로를 확인했습니다. `Agent`는 존재하는 로컬 모델 경로에서 Hub 다운로드 분기를 건너뛰며, 이 패키지는 로컬 tokenizer·encoder 설정과 safetensors 가중치를 사용합니다. 준비된 설정에는 원격 사용자 코드 연결을 위한 `auto_map`이 없고, 실행 경로는 외부 관측 훅을 등록하지 않습니다. 이는 해당 소스·설정 경로 확인 결과이며, 네이티브 라이브러리를 포함한 실제 통신 차단 시험은 별도로 남아 있습니다.

실행기에는 Python 시작 전 설치 해시 확인, 네트워크 capability가 없는 AppContainer, 정지 상태 생성 후 job 배치, 단일 프로세스 제한, 상속 핸들 차단 및 제한된 환경 변수를 구현합니다. worker에는 토큰·capability·컨테이너 식별자·job 제한 확인과 ML 라이브러리보다 먼저 적용하는 Python 감사 훅을 구현합니다. 이 항목들의 소스 구현과 실제 통합 완료는 구분합니다.

`build/offline-integrity.tsv`는 설치 시 생성하는 로컬 변경 탐지 기록입니다. 같은 권한의 공격자가 소스와 기록을 함께 바꾸는 공격이나 관리자·운영체제 침해를 막는 신뢰 기준이 아닙니다. 경로 검사만으로 권한 있는 다른 프로세스의 검사·사용 사이 변경을 완전히 막을 수 없습니다. 조직이 보호하는 설치 경로와 별도의 격리·승인 절차가 필요합니다.

Python 감사 훅은 네이티브 라이브러리와 모든 운영체제 서비스를 중재하는 방화벽이 아닙니다. AppContainer, 오프라인 환경 변수, 모델 해시 및 감사 훅을 각각 전체 반출 방지 인증으로 해석하지 않습니다.

## 통신 검사 판정

UDP 송신 API가 성공을 반환해도 원격 수신자가 받았다는 뜻은 아닙니다. 반대로 OS가 차단했다는 증거도 아닙니다. TCP 연결 거절, 경로 부재, 시간 초과 및 DNS 캐시 응답도 정책에 의한 외부 전송 차단과 구분합니다.

기존 `probe`의 명시적 접근 거부 조건은 유지합니다. 기대한 차단을 관측하지 못한 결과를 통과시키기 위해 조건을 낮추지 않습니다. 네이티브 프로브의 출력 역시 관측 자료이며 그 자체로 업무 입력을 활성화하지 않습니다.

실제 인수에는 동일한 시험 자료를 수신하는 승인된 양성 대조군, 차단 대상 실행, 수신측 관측 및 가능한 경계 패킷 증거가 필요합니다. 공개 합성 식별자만 사용하며 입력 문서·분류 기준·회사 정보를 시험 패킷에 넣지 않습니다. 네트워크가 원래 불통인 환경이나 리스너가 없는 포트에서 나온 실패를 차단 성공으로 대체하지 않습니다.

## 이번 작업의 보안 범위

회사가 승인한 Claude·GPT Enterprise 사용은 기존 업무 흐름으로 유지합니다. 추가 설치하는 Laya 프로세스가 입력·판정 기준·결과를 별도 외부 서버로 보내지 않도록 하는 것이 이번 인수 기준입니다. PC 전체 인터넷 차단, 관리자 권한, 전용 VM 또는 Windows Sandbox 설치를 기본 필수 조건으로 두지 않습니다.

Laya의 실행 중 다운로드·텔레메트리·원격 오류 수집·외부 모델 자동 전환이 없고, 고정 로컬 모델만 사용하며, 필요한 실행 보호가 실패하면 종료하는지 확인해야 합니다. Python과 네이티브 네트워크 경로, 자식 프로세스 제한, 실제 합성 추론을 변경된 실행기에서 함께 검증해야 합니다.

이전 전체 호스트 격리 검토와 현재의 Laya 프로세스 검증을 구분합니다. 다른 프로그램의 동작이나 회사가 승인한 Enterprise 서비스 이용은 이 패키지의 차단 대상에 포함하지 않습니다. 회사 자체 정책이 더 엄격하면 해당 정책을 따릅니다.

현재 HOLD 사유는 새 실행기를 빌드하고 통합 검증하지 못한 점입니다. VM 또는 관리자 권한이 없다는 사실만으로 HOLD를 유지하는 것은 아닙니다. 업무별 독립 정확도 평가와 보류 기준은 보안 인수와 별도로 확인합니다. 현재 버전에는 업무 입력 기능을 제공하지 않습니다.
